# MXroute MCP Server — Implementation Plan

## Context

Build a publish-ready MCP server (`mxroute-mcp`, TypeScript/Node ≥20, stdio transport) wrapping the full MXroute Email Hosting REST API (`https://api.mxroute.com`). Target usage is AI agents, so the design optimizes for tool-calling accuracy: one tool per API operation (43 tools), rich descriptions with workflow guidance, zod-validated inputs mirroring the API's own constraints, structured output with `outputSchema`, and actionable error messages. Source of truth: the OpenAPI spec already in context (`mxroute-email-hosting-api.json`).

SDK: `@modelcontextprotocol/server ^2.4.0` (v2 line — `McpServer` + `registerTool(name, {title, description, inputSchema, outputSchema, annotations}, handler)`), `serveStdio(factory)` from `@modelcontextprotocol/server/stdio`, `zod ^4.2`. Dev: `typescript`, `@types/node`, `vitest`. **No stdout logging — stderr only.**

## Tool catalog (43, snake_case, verb-first)

- **Account**: `get_verification_key` — description documents the add-domain workflow (TXT record `{key}.yourdomain.com` = `domain-verified`, wait for propagation, then create_domain).
- **Domains**: `list_domains`, `create_domain`, `get_domain`, `delete_domain` (destructiveHint), `set_domain_mail_hosting`.
- **Pointers**: `list_domain_pointers`, `create_domain_pointer` (alias vs redirect), `delete_domain_pointer`.
- **Email accounts**: `list_email_accounts`, `create_email_account` (quota MB 0=unlimited, limit ≤9600), `get_email_account`, `update_email_account`, `delete_email_account`.
- **Forwarders**: `list_forwarders`, `create_forwarder` (description covers `:blackhole:`/`:fail:` and the Gmail/Yahoo/AOL → Expert Spam Filtering auto-enable note), `delete_forwarder`.
- **Spam**: `get_spam_settings`, `update_spam_settings` (high_score 1–50), whitelist/blacklist `get_`/`add_`/`remove_` (6 tools, wildcard patterns supported, 409 = already exists case-insensitive).
- **DNS**: `get_dns_records` (MX/SPF/DKIM/verification records for registrar setup).
- **Catch-all**: `get_catch_all`, `set_catch_all` (fail | blackhole | address, address required when type=address — enforced in schema refinement).
- **Quota**: `get_disk_quota` (with grace_period), `get_email_usage` (per-mailbox sizes, hourly refresh noted).
- **Reseller users**: `list_reseller_users`, `create_reseller_user`, `get_reseller_user`, `update_reseller_user`, `delete_reseller_user`, `suspend_reseller_user`, `unsuspend_reseller_user`, `set_reseller_user_package`.
- **Reseller packages**: `list_packages`, `create_package`, `get_package`, `update_package`, `delete_package` (values are strings: number-in-GB/MB or "unlimited").

Every tool: `annotations` (readOnlyHint true for all GETs, destructiveHint true for deletes, idempotentHint where accurate), `structuredContent` + matching `outputSchema` (204 responses → `{ success: true, message }`), and a text JSON content block for backwards compatibility. Failures return `isError: true` with code + hint, never throw raw protocol errors.

## Client & error handling

- Headers on every request; `reseller|user` username form passes through unchanged (documented in config + README).
- Parse `X-RateLimit-*` headers; on 429 surface Retry-After in the error message. No silent auto-retry (writes aren't idempotent) — errors tell the model exactly what to do.
- Non-JSON/HTML error bodies → SERVER_ERROR with HTTP status; network/timeout errors → clear message.

## Tests (vitest, mocked fetch — no network)

- `config.test.ts`: env parsing, missing-var error text.
- `client.test.ts`: header formation, methods/paths/bodies, path-param encoding (incl. `*@trusted.com`), error mapping per documented code, 429 message, non-JSON body.
- `tools.test.ts`: table-driven over all 43 tools — registration names, happy-path request formation (method/path/body), structuredContent conformance, error path (`isError: true`).

## Verification

1. `npm install && npm run build` — clean tsc, zero errors.
2. `npm test` — all vitest suites pass.
3. Inspector smoke: `npx @modelcontextprotocol/inspector --cli node build/index.js --method tools/list` — lists 43 tools without credentials (lazy env validation).
4. Optional real smoke with user-provided creds: read-only `list_domains` / `get_disk_quota` call.
